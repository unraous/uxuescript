# DeepSeek 登录引导与页面查看：Windows 手动验收

本清单验收真实 WebView2 登录、原生点击、焦点与自动返回。自动化通过不代表 GUI 已验收。开发过程中没有退出用户登录、读取或清理 Cookie 数据库、删除 Profile，也没有自动发送模型请求。

## 启动与登录准备

在仓库根目录、能使用 MSVC 的开发者终端执行 `pnpm tauri dev`。本机普通 PowerShell 可用：

```powershell
Set-Location 'F:\26271\11月底面试准备\uxuescript'
cmd.exe /d /c 'call "D:\Vs\Common7\Tools\VsDevCmd.bat" -arch=x64 -host_arch=x64 >nul && pnpm tauri dev'
```

DeepSeek 未设置 incognito 或独立临时数据目录。Tauri 在 Windows 默认使用应用的 `app_local_data_dir` 作为 WebView2 数据目录，登录可跨应用重启保留。**不要删除此目录、浏览器 Profile 或 Cookie 数据库来制造未登录状态。**

若当前已经登录：选择 DeepSeek Web，等待认证检查，点击左侧「显示求解器页面」，在 DeepSeek 网页自己的账号/设置菜单使用官方「退出登录 / Log out」。退出后确认网页已显示登录入口，再选择 Native LLM 并保存、退出应用，开始下面的首次登录测试。若找不到官方退出入口，可跳过未登录测试并记录，不清理用户数据。

注意：界面语言为英文时按钮分别为 `Show solver page`、`Return to course page`、`Save`。下文使用中文称呼。

## 测试一：首次登录，不先保存

1. 在确认退出登录后启动应用，先选 Native LLM。
2. 核对右侧保持超星，左侧没有 DeepSeek 登录提示或查看按钮，右侧没有“超星 / DeepSeek”双切换按钮；原导航、地址、缩放和页面标题仍在。
3. 选择 DeepSeek Web，**不要点保存**。先显示“正在检查”状态；只有服务端确认未认证后，右侧自动显示 DeepSeek。
4. 核对左侧提示“请在右侧登录 DeepSeek，登录完成后将自动返回课程页面。”，此时没有手动查看按钮。
5. 点击右侧登录表单，按官网流程手动登录。输入应可操作；应用不会代替你填写账号、验证码或密码。
6. 登录完成、检查确认身份后，右侧应自动恢复超星；左侧显示“已登录”和独立的“显示求解器页面”按钮。无需先创建 UUID 会话来证明登录。
7. 核对底部紫色“保存”按钮始终存在，位置和样式保持原样；自动返回不会保存配置。

加载检查约 15 秒仍无明确结果或网络查询失败时，显示“无法确认”及“重试”，不会把失败当作未登录自动打开页面。登录引导每次查询完成后间隔约 2 秒再次检查，最多持续约 5 分钟，之后需显式重试继续；等待时间不被当作登录成功的依据。

## 测试二：已登录后的手动查看

1. 点击左侧“显示求解器页面”，核对右侧显示已登录的 DeepSeek，按钮变为“返回课程页面”。
2. 停留几秒，页面不应被重复的登录成功结果自动收起。
3. 在输入框留下几个字作为未发送草稿，点击“返回课程页面”，再显示求解器页面；草稿应仍在，无刷新或新建页面。随后清空草稿。
4. 重复显示/返回几次，核对按钮文字对应实际页面；重复点击或切换中点击不会产生错乱。
5. DeepSeek 前台时，右侧仍保留原控制条，但只控制超星的导航/缩放应禁用，避免误操作后台超星。返回课程后恢复原条件下的可用状态。
6. 保持 DeepSeek Web 选中，在右侧官网菜单手动退出登录，**不要切换求解方式或重启**。等待页面观察与一次网络查询完成，左侧应从“已登录”改为“检查中”再到登录引导，隐藏查看按钮；如果查询失败，应显示未知与重试，不能永久保留旧“已登录”。再次登录后应自动返回课程一次；随后手动查看仍不会被重复检查收起。

## 测试三：求解器与配置页切换

1. DeepSeek 前台时选择 Native LLM：应自动返回超星，隐藏 DeepSeek 状态与辅助按钮，保留登录与 WebView。
2. 再选择 DeepSeek Web：已登录时应保持超星，不再自动弹登录页；认证完成后可手动查看。
3. 快速交替选择两种求解器几次，最终以最后选择为准，不应被旧检查结果拉回登录页。
4. 若在未登录引导中，切到“课程 / 主题 / 通用”子页，右侧应返回课程；登录检查停止，旧结果不能再打开 DeepSeek。返回求解方式子页后才重新检查。
5. 在引导中关闭应用，核对正常退出，没有孤立窗口或卡死。

## 测试四：保存功能回归

1. 修改原有配置，点底部紫色“保存”；配置应按原机制保存，退出重启后可核对。
2. 不点保存，只操作“显示求解器页面 / 返回课程页面”，确认不会触发保存。
3. 首次登录与自动返回也不能替用户保存配置；是否保存求解方式仍由操作者决定。
4. Native LLM 配置面板和原有 API 设置操作应保持正常。

## 补充：异常、遮罩与后台行为

- 网络暂时不可用时进行登录检查，应显示未知/错误与重试；恢复网络后点重试。不能自动断言未登录或反复抢前台。
- DeepSeek 前台打开应用全局确认弹窗，遮罩应覆盖它，弹窗可操作；关闭后恢复原显示。课程区域遮罩仍保留超星原有行为。
- 两种视图下分别最小化/恢复；可选改变系统分辨率/DPI 后核对右侧页面对齐、控制条未被覆盖。Windows 当前强制全屏，不通过解除全屏来制造 resize。
- 后台 JS 可在 **DeepSeek 自己的** DevTools 中放置测试计数器，切回课程等待后再检查同一对象的计数是否增长；这不等于真实模型生成已验证。
- 真实后台生成属于可选验收：须先有有效 UUID 会话、输入为空、无附件且没有在途生成，由操作者显式发起。登录成功并不代表 Adapter 已绑定或模型请求一定成功。不得自动发送测试 prompt。
- macOS WKWebView 仍需实机验收。

开发调试时，**本地 main** 控制台可执行以下只读查询（远程页面无此权限）：

```js
await window.__TAURI_INTERNALS__.invoke("current_webview");
await window.__TAURI_INTERNALS__.invoke("deepseek_authentication");
```

第二项会在需要时 ensure 同一 DeepSeek WebView，并发起一次只读认证查询，不显示页面、不保存配置。结果为四态及固定诊断码，不能包含凭据或用户资料。

反馈请记录失败步骤、选中的求解方式、实际可见页面、认证状态/诊断码、显示缩放及相关日志。不要分享凭据、Cookie、完整会话 URL 或私人对话。
